# 冒险岛提醒 · Windows 图形界面版

## 当前交付状态

**本压缩包是图形界面源码与打包工具，尚不含可直接运行的 .exe。** 已完成界面、打包脚本和自动构建流程；开发环境为 Mac，尚未在 Windows 生成或实测最终程序。不能将此源码包直接当成免 Python 成品分发给普通用户。

## 普通用户：拿到成品后怎么用

打包并完成 Windows 实测后，分发 `MapleAlert.exe` 和本说明。普通用户无需安装 Python、无需输入命令。

1. 双击 `MapleAlert.exe` 打开窗口。
2. 点击“测试声音与通知”，确认听到声音并看到通知。
3. 将游戏保持为窗口化或无边框窗口，固定位置和大小。
4. 选择游戏所在屏幕，点击“1 选择游戏区域”。在截图上框选整个游戏区域，Enter 确认，Esc 取消。**无需等待测谎仪出现，也无需框选测谎仪。** 已内置三个绿色准头的形状检测，不依赖弹窗文字。
5. 点击“2 检查画面”，确认捕获到正确游戏区域。画面仅预览，不保存截图；没有三个绿色准头时，匹配分数低是正常的。
6. 点击“开始监控”。将工具窗口移出被监控区域，或最小化；游戏画面必须保持可见。
7. 点击“停止”结束监控。关闭窗口会退出程序，最小化仍会监控。

默认模式依据用户提供的 IMG_7972.JPG，提取绿色准头的二值形状模板。先按绿色筛选像素，再寻找形状匹配、大小接近、横向排列、基本同高且间距接近的至少三个准头；不会读取星形图案、判定图形答案或控制鼠标。单个/两个准头和普通绿色块不足以提醒。检测不依赖弹窗标题或语言，但只在三个准头实际可见时有效。其他游戏场景若有相同三图标排列仍可能误报，不能仅凭一张样本估计准确率。

图中提示“1 秒后”，因此目标采样间隔为 0.25 秒，同一帧匹配三个准头即可提醒。真实提前量取决于图形显示时长和处理耗时，不保证提前 1 秒。默认支持 0.75–2 倍之间的 8 个离散尺度，并非保证覆盖任意缩放。

数据保存在 `%LOCALAPPDATA%\MapleAlert`，包含区域配置；旧版自选模板可能仍保留。截图检测在内存进行；不联网、不上传、不读取游戏进程、不模拟键鼠、不识别或解答验证码。主界面可打开配置文件夹。重新选择游戏区域会启用三个绿色准头检测；旧配置文件夹中的个人模板可在不需要时手动清理。

三个绿色准头模式默认：阈值 0.88，目标采样间隔 0.25 秒，同一帧同时匹配三个准头才提醒；连续 8 帧未命中才重新准备报警，两次报警至少相隔 30 秒。图像处理慢时实际间隔会更长。图形持续存在只报一次。声音和通知发送失败会显示在主界面。


## 生成成品：只需准备一次

需要一台 Windows 10/11 x64 电脑和官方 Python 3.12 x64（包含 Python Launcher 和 Tcl/Tk，使用默认安装选项）。下载：https://www.python.org/downloads/windows/

1. 将本源码包解压到可写文件夹。
2. 双击 `build.bat`。脚本创建独立打包环境，联网安装依赖，运行逻辑测试，生成单文件无命令行窗口的程序，再执行打包后自检。
3. 显示 `Build complete` 后，在打开的 dist 文件夹中找到 **`MapleAlert.exe`**。
4. 先按下面的 Windows 实测清单验证。通过后把 exe 发给其他人即可，收件人无需 Python。

脚本失败时不要分发残留 exe；查看窗口中的错误。打包自检失败的详情在 `%TEMP%\MapleAlert-build-error.txt`。需要测试源码界面时，构建环境准备好后可双击 `start-source.bat`。

PyInstaller 会把运行所需的 Python 和库打入 exe。单文件第一次打开会先解压到系统临时目录，可能需要等待片刻。此构建未附数字签名；分发环境若要求签名，应由分发者签署，不能把关闭安全防护作为安装步骤。

## 可选：用 GitHub 自动构建

适用于有 GitHub 账号、希望避免在自己的 Windows 电脑安装打包环境的人。项目根目录已带 `.github/workflows/build-windows.yml`；此交付没有创建仓库、上传源码或运行云构建。

1. 将本文件夹中的源码上传到自己的 GitHub 仓库根目录，保留 .github 文件夹；不要上传个人模板或配置。
2. 在仓库 Actions 中选择“Build Windows desktop app”，点击 Run workflow。
3. 构建成功后，在该次运行的 Artifacts 下载 `MapleAlert-Windows-x64`。
4. 解压获得 exe，在 Windows 进行下述实测后分发。

云构建只生成程序，不接触你的游戏画面。依赖下载、构建本身需要网络；生成的工具运行无需网络。工作流会检查库打包、合成模板匹配和 Tk 窗口初始化，不能替代真实游戏测试。

## Windows 实测清单

- 在没有 Python 的 Windows 电脑双击 exe，应出现中文界面且没有命令窗口。
- 点击测试按钮，检查系统音量/音量混合器、通知设置、勿扰或专注助手。
- 只需框选一次游戏区域，取消不应覆盖已有配置；普通游戏画面也能完成配置。
- 在当前显示缩放（例如 100%、125%、150%）下检查画面与选区一致；多屏各测试一次。
- 显示包含三个绿色准头的真实画面，应提醒一次；持续显示不重复。短暂出现的图形尤其需要在实机验证。
- 隐去目标至少 3 秒，距上次提醒超过 30 秒，再出现应再次提醒。
- 监控过程中点击停止，后续不应继续提醒；关闭退出后不应再截屏。
- 在正常游戏和其他对话框下观察误报；通过阈值校准，如仍无法区分应补充新的界面样本后更新预设。先收集正常与目标画面的分数，确保阈值能将两者分开。

保持游戏可见；最小化、被遮挡、切换桌面、睡眠或锁屏时可能漏报。移动或缩放游戏窗口、更换显示分辨率后须重新设置。受保护而无法截图的游戏画面无法监控；本程序不绕过捕获限制。识别和系统通知均不保证必然送达。

## 文件

- app.py：图形界面、框选、预览和后台监控。
- alert.py：屏幕捕获、模板匹配、提醒与连续命中逻辑。
- build.bat：Windows 本机构建脚本。
- .github/workflows/build-windows.yml：手动触发的 Windows 云构建流程。
- test_alert.py / test_profile.py：报警逻辑、通知错误隔离与内置双特征匹配测试。
- green_targets.py / assets/green-target-1.png 等：默认三个绿色准头检测及二值图形模板。
- detector_profile.py 和其余 assets：保留上一版固定文字双特征模式的兼容代码。
- test_green_targets.py：三准头、数量不足、排列错误、颜色与形状不符及缩放测试。
